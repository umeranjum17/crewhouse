# The crew list: only Chief says "Needs you"

One install is one person, and the person talks only to Chief. A crew member waiting on
the person reads **Waiting** (the neutral seat word and style); only Chief says **Needs
you**. The ask itself reaches the person through Chief (Home's Needs you rows), so no crew
row wears the red needs style. The crew rail (`SideCrew`, the desk's `Your crew` column)
and the crew page (`#/crew`) both follow this.

## Sub-features

- `rail` — the desk rail beside Chief (`web/src/main.tsx` `SideCrew` → `A.statusOf`): a crew row with an ask reads `Waiting`, never `Needs you`. The count line under Chief (`SideCrew`'s sub) is the Office's own summary (`A.summaryOf`, every member once, Chief too), so its numbers count the same per-member status each row shows — a `Waiting` row is never counted as free (the reported bug: the sub read `1 resting` while the only member showed `Waiting`). No crew rail row carries an unread badge, even with an unread reply (only Chief does).
- `page` — `#/crew` (`web/src/main.tsx` `Crew`): a crew row's status word is neutral (`Waiting`), never `Needs you`; a working row keeps its green dot.
- `phone` — the native app's `Your crew` screen (`mobile/App.tsx` `HelperPill`/`Pill` → `mobile/src/crew-status.ts` `crewPill`/`chiefPill`, the web rail's own `A.statusOf`/`A.chiefStatus`): each helper pill reads the same word **and dot colour** as the desk rail for that member (a working helper (one gone quiet too) is a hollow ink ring, a failed one red, a free one `Free` grey, not `Free to help`), and Chief's own row reads `A.chiefStatus` (`Free`/`At work`/`Waiting`/`Needs you`) with the rail's own dot (grey, pink only for `Needs you`) — never the helper's hero line. A member missing from the office view across a refresh falls back to the helper's own words, never a second status rule.
- `office` — the Office view (`web/src/office.tsx` `glowOf`/`TITLES`, `mobile/src/office.tsx`): a crew panel/group/row reads `Waiting`, never `Needs you`; the glow class and colour are kept. A waiting crew member leads with what it is on (job title or step) and `Waiting for Chief`, never the ask's head, and has no answer/approve button.
- `office-chief` — the asks reach the person once, through Chief: Chief's panel (desk) or the top of the grouped list (phone) carries one action, `Chief has N things for you` (`A.chiefHas`, N = Needs you's length), opening Chief (`#/chief`; the native phone goes to the Chief view). The Office pins no Needs you (only Chief's thread does), and only its bar stays put while the rows scroll. Only a crew member on a job waits (its job over `Waiting for Chief`); one with an ask but no job rests and Chief carries the ask. A done row's meta is the finished job's title, never a waiting status. One status everywhere (`A.groupOf`): the header counts, the rows, On it now (`Nobody is working: N waiting for Chief.`) and Chats agree, and only Chief's chat row carries a dot for an ask; Chief's panel says `N waiting for Chief`, and a crew step reads `Asked Chief for an OK`.
- `chats` — Home's existing Chats list (`A.chats`, web `Chats`, native `ChatList`), as mock 2 (`data/ch-grok-samples/mocks/png/2-crew-390-{day,night}.png`): Chief first, then the crew in the Office's group order (waiting, at work, done, free; newest first inside a group), The crew last. It keeps the last message and its time separate from the end-column office status. Chief's row carries his open asks (`Chat.asks` = `counts.needs`) as a round blue count in place of a status word; no crew row has a count. A working member has a `<name> is working` line under the row, its green dot on the line's first line when it wraps. The preview is one line with an ellipsis at every text size (the only thing on the row that truncates: name, time and status never do). Every avatar, The crew's pair too, sits on a round disc one step from the row (`discOf(who, true)`; native `rowDisc`). On the phone at large text (`width / fontScale < 360`) the time and status (or Chief's count, which grows with the text) sit under the preview, and a transcript's name column grows with the text size, so neither breaks a word.
- `unread` — a thread's NEW divider precedes the first unread message on opening. `GET /api/bots/:id` includes `bot.last`, `bot.unread` and `bot.firstUnread`, from the same query as state. Crewd's own unseen predicate owns the first message id (`null` when read); the client never reconstructs it from filtered messages or limited task history. On the phone the thread opens scrolled to the end with NEW in view (the scroll waits one frame after the live page's lines grow the content; in the same frame Android ignored it). The opening boundary remains after `/read` clears the count; leaving and reopening a read thread removes it. Completed Chief-assigned tasks in helper threads do not count twice.
- `chief` — Chief's own word is `Needs you` (rail `.side-status`, `A.chiefStatus`, the Office `ChiefPanel` glow), unchanged.

## How to get to it (user POV)

- Home opens on Chat with Chief; the rail is the `Your crew` column on a desk (≥900px wide).
- `#/crew` is Home's `Your crew` page (the `Your crew` label in the rail, or the crew list on a phone).

## Driving it with the browser

Preconditions: `?demo` runs the mixed demo crew whose Tracer waits on the person (no crewd);
`?demo=crew5` is the layout crew. Drive the real crewd to an open ask when proving the live path.

- **Crew page words.** Open `?demo&night#/crew` at 1440; `eval` `[...document.querySelectorAll('.crew-row .status-word')].map((e) => e.textContent)` — no entry is `Needs you`, and a waiting helper (Tracer) is `Waiting`.
- **Rail words.** Open `?demo&night` at 1440 (the rail is desk-only); `eval` `[...document.querySelectorAll('.side-row .side-seat')].map((e) => e.textContent)` — no entry is `Needs you`; and `document.querySelector('.side-status').textContent` is `Needs you` (Chief).
- **Rail summary line.** On the same desk rail, `eval` `document.querySelector('.side-sub').textContent` — its `N waiting · N at work · N done · N free` numbers equal the `.side-row .side-seat` words' own groups plus Chief's `.side-status` (unless `Needs you`), never a `resting` count (`A.summaryOf`; drive the real crewd for the live path).
- **Office words.** Open `?demo&night`, tap Office in the bar; `eval` `[...document.querySelectorAll('.office .p-state')].map((e) => e.textContent)` (desk) or `[...document.querySelectorAll('.office .grp')].map((g) => g.getAttribute('aria-label'))` and each row's `.p-state` (phone) — no crew panel/group says `Needs you`; Chief's panel does.
- **Office asks via Chief.** In the same Office, `eval` `[...document.querySelectorAll('.office .btn')].map((e) => [e.textContent, e.getAttribute('href')])` — exactly one entry, `Chief has N things for you` → `#/chief`, and no panel/row text has `has a question`, `Review … order`, `needs your OK` or `Answer …`; a waiting row ends `Waiting for Chief` (its meta, or its line when it has no job or step). Tap it: the hash becomes `#/chief`. Also `document.querySelectorAll('.needs-pin').length` is 0 in Office and the Chief view still has `.home-chat .needs-pin`; scroll to the bottom at 390 and check no `Needs you` card and no half row under the bar.
- **Chats, live path.** Start isolated crewd with `CREWHOUSE_ENGINE=stub`. Recruit Scout and Reel through `/api/recruit`; hold Reel with a natural request containing `ask permission`. Finish a Scribe invoice job using `CREWHOUSE_STUB_GOLDEN=1` and `Sort out my invoices` for readable fixture words. To reproduce a resting row, send Scout `hit every limit`, wait for its task to pause, then send a plain `Please check the Friday flights.` while the accounts rest. Open Home → Office; on a desk tap Chats' `See all`. Read each visible `.list-row .small`, `time`, `.p-state`, `.badge`, and `.chat-working`. Scout shows its request and time beside `Waiting`, Reel shows `At work` with its working line, and only Chief can have a badge (his open asks; with Scout gone quiet past `CREWHOUSE_STUCK_MS` it is 1). The rows run Chief, waiting, at work, done, free, The crew. The scripted rest expires after two minutes: re-drive it rather than claiming a later free row is a waiting-row proof.
- **NEW, live path.** Leave Chief's thread, finish a new Chief turn, then open `#/chief`. Capture `.new-divider` directly before that reply; poll `/api/state` until Chief's unread is zero and verify the divider still exists. Leave and return: no divider until a fresh unread turn. Repeat themes and widths with a fresh turn for each opening. `node --test --test-name-pattern='live Chats' test/office.test.ts` pins the read/return journey with a real HTTP server and browser.
- **Largest text.** Chats intentionally stays phone-only: the full-width desktop Office hides its old side feed. Capture Chats at 390 and a thread at 390 and 1440; at 1440 compare Office/rail status words with those phone rows. Scale every computed font size and line height 1.3× (read sizes before writing any, as `look-check.mjs` does). At 360 run `look-check.mjs web --person <owned-person.key> --out <evidence> --then '<Office switch and Chats See all>' chats=<base>/`; run Chief's thread separately without the switch. On native, pair the owned emulator, open Office, then run `SERIAL=<owned> node .../look-check.mjs android --out <evidence> --then 'optional:^Office$>>reveal:^CHATS$' chats`, then repeat Chief's thread. `optional:` only skips a route tab that has already scrolled away; `reveal:` must actually find its label or fails. The checker uses the active `wm size` override, restores any density override, and uses 2.0× text on Android 34+. For a loopback dev lab, `--reverse device:host,device:host` reinstalls only the explicitly named task-owned adb forwards during configuration changes; it is not a production network proof. Add the approved Chats mock to `mocks.tsv` when dispatched against a new approved direction.
- **Themes/widths.** Repeat at `?day`/`?night` and 1440 (desk) and 390 (phone, the rail is hidden; the crew page is the list).
- **Installed app.** Launch Chrome in app mode (`--app=<url>`, `matchMedia('(display-mode: standalone)')` true) and repeat — no standalone-only code, so the words are identical.
- **Phone crew list (native).** The Android app is its own surface: pair it (`phone-pairing.md`), open Settings (the gear) then `Your crew`, and read each helper's pill (`adb -s <serial> shell uiautomator dump` → the pill text). It must equal the desk rail's `.side-row .side-seat` word for the same member on the same crewd — a working helper `At work` (a quiet one too), a free one `Free` — not the helper's job title. Capture day and night (`adb shell cmd uimode night yes|no`).

## Gotchas

- The Office view's own grouping (`glowOf`, `TITLES`, the phone's grouped list) is covered too: a crew panel/group reads `Waiting`; only Chief's panel says `Needs you`. Its glow class/colour is unchanged.
- The avatar ring (`h.ring === 'needs'`) is the "this helper has an ask" cue, not the seat word; it stays.
- `?demo` intercepts every API call, so it proves the words, not the live counts; drive the real crewd for the live path.
- Android `look-check` reports each Chats preview's drawn ellipsis as `clipped` (uiautomator returns the full text): that one-line cut is the design; any other `clipped` hit on a Chats row (name, time, status, working line) is a real defect.
