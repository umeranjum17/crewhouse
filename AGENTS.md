# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Checks: `npm run check` (tsc, strict) and `./crewhouse test` (a throwaway HOME, then a check that the owner's `~/.pi` sign-ins, settings and extensions are byte-for-byte unchanged). Run both before committing; CI (`.github/workflows/ci.yml`) runs them plus the web build on Node 22.19 and 24, so tests must never need an account, the network or a model: they run the real engine on the stub model (`src/stub.ts`, `CREWHOUSE_ENGINE=stub`; its script is in the file header).
- Tests wait on a condition with a bound, never a fixed sleep: CI's disks are slow. Use `test/lab.ts` (`setup`, `until`, `settled`, `holding`, `release`); daemon tests take an OS-assigned port. A session file only exists once the model has answered once (Pi writes it lazily).
- Node runs `src/*.ts` directly with type stripping: no parameter properties, enums or namespaces (tsconfig sets `erasableSyntaxOnly`). Imports use `.ts` extensions.
- Size budget: crewd (`src/`) stays under 5,000 lines, per the product plan. Prefer deleting to adding.
- The engine is Pi, pinned exactly in `package.json`, in-process (`src/engine.ts`): one session per task in the bot's folder, one `ModelRuntime` per member (`src/accounts.ts`). No Claude (Anthropic forbids subscriptions outside its apps), no Herdr, no CLIs. Bump Pi deliberately: `test/isolation.test.ts` (decoy `~/.pi`, `~/.agents` and a hostile env; an fs tracer) and the stub suite are the gate.
- Every module that imports Pi imports `./isolate.ts` first: it clears inherited `PI_*`/provider-key env and sets the engine's own dir before Pi evaluates (Pi reads `PI_PACKAGE_DIR` at import). `src/main.ts` statically imports only `isolate.ts`, `config.ts` and `node:` modules and loads the rest with `await import` (test/onboard.test.ts fails otherwise). `openSession` switches Pi's resource discovery off by swapping the loader's package manager; the isolation test catches a Pi bump that moves it.
- Sign-in is `@byokit/accounts` (repo umeranjum17/byokit): `src/accounts.ts` only picks the offered accounts and each member's credential file; resting, `classify()`, `isolate()` and the fs tracer come from the kit too. Pinned exactly, from npm; bump it like Pi, with the isolation test as the gate. App connections stay in `src/connections.ts`. ChatGPT signs in by redirect: crewd listens on ChatGPT's fixed port 1455 itself (Pi then finds it taken and waits for the pasted address), so the tab shows Crewhouse's page only once the sign-in works; the device code is the fallback. Tests take a free port via `CREWHOUSE_CALLBACK_PORT` and mock OpenAI's token endpoint with `fetch`.
- Policy is `src/policy.ts` `effectOf`, called from the engine's `tool_call` hook (`Crew.gate`): unknown tools fail closed. Work in the bot's space and the bubblewrap shell never asks; spending never gets a standing answer (its effect has no `key`). Card words come from the tool and its input, never the model. Command-line tools needing the person's sign-in are typed host tools (`run.free`/`run.spend` in `tools/<id>/tool.json`), never shell.
- Tool kit: manifests in `tools/*/tool.json`, logic in `src/tools.ts` (`resolveGrants`, `installTool`). Tests set `CREWHOUSE_TOOLS_DIR` to a temp dir; a real `./crewhouse tools install` downloads Chromium (~170 MB).
- Which account a task runs on is picked in `src/crew.ts` `run()`: its own `brain` first, then the bot's `models` in `bot.json` (keys of `PROVIDERS` in `src/accounts.ts`), skipping resting and signed-out ones. An account's error goes through the kit's `classify()` and `failover()`, which reopens the task's own session file on the next account.
- Household members (`people`, id 1 = owner): bots, tasks, messages and asks carry `member`; a run uses the task member's own runtime and `people/<id>/engine/auth.json`; rests are keyed `<member>:<account>`. Never fall back onto another member's account (vendor terms). App connections (`src/connections.ts`) are per member too.
- API responses to the app carry no commands, paths, model or engine ids, percentages or prompts (`Crew.pub`/`task`/`askView`; asserted in `test/stub.test.ts`). The web app reads crewd only through `web/src/adapter.ts`; the contract is `docs/ui-contract.md`.
- Anything time-based is a row in `routines`, fired by `Crew.schedule()` from crewd's own tick (schedule words in `src/routines.ts`); no cron, no timers per routine. Tests move `next_at` into the past and call `crew.schedule()` instead of waiting.
- Restart is a non-event: in-memory state in `Crew` (holds, live sessions, handoffs) must be rebuildable from SQLite plus the session files (`tasks.session`). `Crew.recover()` requeues running tasks, and `run()` reopens each one's session file; a parked question stays open and the resumed bot's retried call finds it. `test/restart.test.ts` kills a real crewd mid-run.
- Every `notes.md` change is a git commit in the bot's own folder (`src/bots.ts` `remember`/`forget`); Undo edits lines back rather than `git revert`, which conflicts on adjacent notes.
- Chief's voice rules live in `templates/chief/AGENTS.md`. First run is the app's Hello screen (greeting by the member's name, three ideas); tapping one calls `onboard(address, member, ask)`. The written `chiefGreeting` in `src/crew.ts` only greets a thread nobody has opened from Hello. A task with no usable account waits (`paused`, `wake_at` NULL) and `Crew.wake()` starts it once that member signs in.
- The web UI is plain React bundled by `scripts/build-web.mjs`, on design direction C "Pocket Pals" (night mode and ASCII moments from A). Screens read only the plain-words view models in `web/src/adapter.ts`, never crewd rows; what the UI needs from crewd is `docs/ui-contract.md`, and `test/ui.test.ts` fails if a command, path, model name, percentage or monospace text can reach a screen. `?demo` runs every screen on `web/src/demo.ts`. `tokens.ts`, `art.ts` (the mascots as dot bitmaps), `adapter.ts` and `api.ts` stay framework-free, so the future Expo app can reuse them. It bundles `@desklink/react-native`'s `*.web.*` build with `react-native` aliased to `web/src/rn-web.tsx`; tsc checks `web/src/desklink.d.ts` instead of the package's Metro sources, and `.npmrc` (`legacy-peer-deps`) keeps its Expo peers out.
- Bot desktops live in `src/desktop.ts` (Xvfb + the bot's Chromium + one desklink engine per bot). A distro Chromium wrapper can add Wayland and scale flags; the bot's flags come last so they win. Never let a bot process see the owner's `WAYLAND_DISPLAY` or X cookie.
