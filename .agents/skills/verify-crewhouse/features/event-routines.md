# Event routines

## Fixture journey

Run `node --test test/event-routines.test.ts` with a disposable HOME, full XDG mask,
TMPDIR and dead D-Bus address, through the memory gate. This is crewd's real scheduler,
SQLite, BYOKit connection sign-in and stub engine; Google responses are synthetic.
It checks literal sender/subject matching, a first-look baseline, opaque history IDs
larger than JavaScript's safe integer, pagination, incoming mail only, failed reads
preserving the cursor, missed ticks, restart deduplication and a calendar delete
still waiting on its usual approval. Chief's message must name the triggering mail.
The event cursor commits in the same SQLite transaction as the task and fire event.

connection handoff and OpenCode Go `muse-spark-1.3-contributor` setup first: never copy

stop and name that missing handoff; neither fixture Google nor another model qualifies.

   approve the existing routine card. The `on` words are e.g.
   `when an email from umeranjum17@gmail.com with subject Event routine proof arrives`.
   Check the routine list shows those words and its initial history baseline is stored.
2. Send exactly one authorized email from `umeranjum17@gmail.com` to the same address.
   Wait on the recorded `routine.fired` event and Chief's message, not a fixed sleep.
   Google is polled once a minute from crewd's tick. Capture the matching mail envelope,
   the task, fire record and the app's resulting message without exposing credentials.
3. Ask Chief for `10 minutes before each meeting`, approve its card. Create one uniquely
   named test event using Calendar's normal approved add path. Its start should be just
   over ten minutes ahead, so the next poll witnesses the reminder. Keep all-day and
   cancelled events out; subsequent ticks and a candidate restart must not start it again.
4. Delete only that test event using the normal Calendar delete approval. Do not delete
   the self-addressed email unless separately authorized. Remove the test routines.
