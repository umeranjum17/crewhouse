# The Pi flag

Part of the crewhouse verification map. Source: `docs/verification/pi-engine.md`.

## How to get to it (user POV)

Start Crewhouse with `CREWHOUSE_ENGINE=pi` on a built kit and send Chief a message: the answer shows in his thread, from Pi. Ask two helpers at once and each answers in its own chat on its own Pi, with the tools from its own extension list (`extensions.json` in its folder, `src/pi/extensions.json` the default). A bot on `notes` keeps its own notes in `<state>/pi/<bot>/work/notes.md`, shown to it once as each job starts, across a restart and with no session left. Without the flag nothing changes. Every bot's Pi runs behind bubblewrap with its own folder the only writable place on disk, or does not start. A turn that has made 20 tool calls without a word is asked once for its answer, and the kit's cap of 30 ends one that still keeps going.

## Driving it

1. Needs `node scripts/prepare-pi.mjs` once, and a MiniMax key file already on the machine.
2. Run `done-done run pi-engine` with `MINIMAX_KEY_FILE` set (or `scripts/verify/pi-engine.sh <out> <key file>`); it boots its own labs and tears them down.
3. Capture: `flag-off/` (the bot list and a chat), `flag-on/{scout,scribe}-{390,1280}-{day,night}.png`, `flag-on/installed/{scout,scribe}-390-{day,night}.png`, `crew.txt`, `offered.jsonl`, `pi-folder.txt`. The journey's exit code is the verdict: it also fails when crewd did not start on Pi, the chat's words are not Pi's, a helper lost its own word or knows the other's, a model call offered any tool but that helper's own, the model calls pass `PI_CALL_LIMIT` (20 unless set; `offered.jsonl` keeps every call, what each tool said and the notes each prompt showed), a code was not recalled from the notes that job's prompt showed, the other's code or word reached anything sent to the model or a session, a job's notes changed between its rounds, a Pi runs that should not, or the stand-in Pi folder changed.
4. The wall: `done-done run pi-wall` (`node scripts/verify/pi-wall.mjs <out>`), no key, nothing spent. Captures `no-wall.txt` (the escape lands), `with-wall.txt` (refused in the plain line, a write inside lands), `launcher.txt`, `mounts.txt`, `no-sandbox.txt` and `flag-off.txt`. Its exit code is the verdict, from what the host sees.
5. The answer: `done-done run pi-answer` (`node scripts/verify/pi-answer.mjs <out>`), no key, nothing spent. A real crewd on the flag with a model that only calls tools. Captures `answered.txt` (asked once after twenty calls, answers inside the cap of thirty), `stopped.txt` (a model that keeps going ends on the stopped-turn line, with one `run.limit` event for that job), `plain.txt` (a plain turn: no call, no ask) and `flag-off.txt`. Its exit code is the verdict, from the model's own requests, the chat and crewd's events table.
6. The room: `done-done run pi-room` (`node scripts/verify/pi-room.mjs <out>`), no key, nothing spent, on a login with a user manager. Captures `no-room.txt` (the read climbs past the ceiling, the bot reaches everything), `ceiling.txt` (one bot stopped while two answer), `memory.txt` (per-bot numbers before and after), `door.txt`, `ports.txt`, `service.txt` (each OOM policy on a real user service) and `flag-off.txt`. Its exit code is the verdict, from what the host sees.
7. Sign-in: `done-done run pi-signin` (`PI_SIGNIN_SHOTS=on node scripts/verify/pi-signin.mjs <out>`), no key, nothing spent; needs `node scripts/prepare-pi.mjs`, `npm run build:web` and a task-named `CHROME_DEVTOOLS_AXI_SESSION`. The user's view: with no AI account Chief's job waits, "Sign in with MiniMax" opens the key sheet, a wrong key is refused in plain words, the right one signs in and the waiting job answers by itself. Captures `signin.txt` (the transcript), `signin-1-refused-{day-390,night-1280}.png`, `signin-2-signed-in-{day-390,night-1280}.png`. Exit 0 means the key was on no disk in the clear and sat sealed in `<state>/pi/signins/`, a stand-in `~/.pi` hashed the same, a restart kept the sign-in and a second job answered, and signing out removed the key. The app hides the scripted model's reply lines: for Chief's real answer run `pi-signin-real` (`MINIMAX_KEY_FILE`, about ten tiny live calls, parked by `done-done verify` until approved), which adds `signin-3-chief-{day,night}-{390,1280}.png`.
